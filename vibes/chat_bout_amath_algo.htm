I have a finite list of random numbers 1,5,16... Etc, operators ie +,-,/,* and =. I want to form all valid equations that use that components WIHOUT replacement ie 2,4,6,8,+,= would be 2+4=6 2+6=8. How to do this algorithmically optimized for speed. Assume pemdas operations and chainable +- signs ie 8+-6 but not chainable /* use dynamic programming method

ChatGPT said:

I’m going to frame this as a subset dynamic-programming problem, because that’s the cleanest way to avoid recomputing the same expression fragments over and over. Then I’ll show how to enforce “no replacement,” PEMDAS, and the + - chaining rule.

Use DP over subsets.

The fast way is:

  1. Build all possible valid expressions from every subset of your tokens.

  2. For each subset, store the value(s) that subset can make.

  3. Then look for two disjoint subsets that produce the same value:
    expr_left = expr_right

That avoids brute-forcing every full token permutation.

Core idea

Suppose your numbers are:

[2, 4, 6, 8]

and operators available are:

['+', '=']

You want:

2+4=6
2+6=8

with no replacement, meaning each number occurrence can be used at most once per equation.

So treat each number as a unique item by index, not just by value.

DP state

Let:

dp[mask] = all values achievable using exactly the numbers in `mask`

where mask is a bitmask over the number list.

For each achievable value, also store one or more expressions that make it.

Example:

dp[0b0011] might contain:
    6 -> ["2+4"]
    -2 -> ["2-4"]
    8 -> ["2*4"]
    1/2 -> ["2/4"]

Why this is dynamic programming

Because every larger expression is built from two smaller disjoint subsets:

A op B

If left_mask and right_mask are disjoint and union to mask, then:

for x in dp[left_mask]:
    for y in dp[right_mask]:
        combine with +, -, *, /

So each subset is solved once, then reused.

PEMDAS handling

The easiest method is:

  • Store each expression node with:

    • value

    • string

    • precedence

When combining:

  • add parentheses only when needed

Example:

  • 2+(3*4) does not need parentheses around 3*4

  • (2+3)*4 does need parentheses around 2+3

Use precedence levels like:

atom = 3
* /  = 2
+ -  = 1

Chainable + - but not * /

That means:

  • You allow flat additive chains like:

    • 8+-6

    • 2+3-4+5

  • But multiplication/division chains must still be binary-tree grouped, not flattened into a weird token chain like 8/*6

Algorithmically, the simplest interpretation is:

  • Build normal binary expression trees

  • Permit repeated + and -

  • Permit repeated * and /

  • But when printing, flatten only additive trees

That gives fast evaluation and valid formatting.

If you want to be stricter, you can tag expression types:

  • additive-chain

  • multiplicative

  • atom

and only flatten additive-chain nodes.

Optimized DP structure

For speed, do this:

1. Represent values exactly

Use rational numbers, not floats.

In Python:

Python
from fractions import Fraction

That avoids precision errors like 0.1 + 0.2.

2. Deduplicate by value

For each subset, store:

value -> one expression

or maybe a small list of expressions if you want all forms.

This is the biggest speed win.

If you only need one equation per value, store just one expression.

If you need all equations, store all distinct expression forms, but that can explode.

3. Partition each subset only once

When splitting a subset into two parts, only consider partitions where:

left_mask < right_mask

to avoid symmetric duplicates for commutative operators.

4. Use operator pruning

For commutative ops:

  • a+b and b+a are same value structure

  • a*b and b*a same

So only generate one order for + and *.

But for - and /, generate both directions.

DP recurrence

For each non-singleton subset mask:

  1. Enumerate all proper submasks left

  2. Let right = mask ^ left

  3. Require left < right to avoid duplicate splits

  4. Combine every result from dp[left] with every result from dp[right]

Pseudo:

Python
for mask in all_subsets:
    for left in proper_submasks(mask):
        right = mask ^ left
        if left >= right:
            continue

        for x in dp[left]:
            for y in dp[right]:
                add(x + y)
                add(x * y)
                add(x - y)
                add(y - x)
                if y != 0: add(x / y)
                if x != 0: add(y / x)

Base case:

Python
dp[1<<i] = { numbers[i] : str(numbers[i]) }

Forming equations

Once dp is built, find two disjoint subsets with a common value.

For every pair of disjoint masks A, B:

  • for each value v in both dp[A] and dp[B]

  • emit:

    exprA = exprB

If you want to use all available components exactly once, then require:

A & B == 0
A | B == full_mask

If you only want equations using any subset without replacement, just require:

A & B == 0

Python-like implementation

Python
from fractions import Fraction
from collections import defaultdict

class Expr:
    __slots__ = ("value", "text", "prec", "kind")
    def __init__(self, value, text, prec, kind):
        self.value = value      # Fraction
        self.text = text        # string
        self.prec = prec        # 3 atom, 2 mul/div, 1 add/sub
        self.kind = kind        # "atom", "add", "mul"

def wrap(child, parent_op, is_right=False):
    # parent_op in "+", "-", "*", "/"
    parent_prec = 1 if parent_op in "+-" else 2

    need = False
    if child.prec < parent_prec:
        need = True
    elif is_right and parent_op in "-/" and child.prec == parent_prec:
        need = True

    return f"({child.text})" if need else child.text

def combine(a, b, op):
    if op == "+":
        text = f"{wrap(a, '+')}+{wrap(b, '+', True)}"
        return Expr(a.value + b.value, text, 1, "add")

    if op == "-":
        text = f"{wrap(a, '-')}-{wrap(b, '-', True)}"
        return Expr(a.value - b.value, text, 1, "add")

    if op == "*":
        text = f"{wrap(a, '*')}*{wrap(b, '*', True)}"
        return Expr(a.value * b.value, text, 2, "mul")

    if op == "/":
        if b.value == 0:
            return None
        text = f"{wrap(a, '/')}\/{wrap(b, '/', True)}"
        return Expr(a.value / b.value, text, 2, "mul")

def submasks(mask):
    s = (mask - 1) & mask
    while s:
        yield s
        s = (s - 1) & mask

def build_dp(numbers, allowed_ops={"+", "-", "*", "/"}):
    n = len(numbers)
    size = 1 << n
    dp = [dict() for _ in range(size)]

    # base
    for i, x in enumerate(numbers):
        mask = 1 << i
        dp[mask][Fraction(x)] = [Expr(Fraction(x), str(x), 3, "atom")]

    # build
    for mask in range(1, size):
        if mask & (mask - 1) == 0:
            continue  # singleton

        results = defaultdict(list)

        for left in submasks(mask):
            right = mask ^ left
            if left >= right:
                continue

            for xv, xexprs in dp[left].items():
                for yv, yexprs in dp[right].items():
                    for xe in xexprs:
                        for ye in yexprs:
                            if "+" in allowed_ops:
                                e = combine(xe, ye, "+")
                                results[e.value].append(e)

                            if "*" in allowed_ops:
                                e = combine(xe, ye, "*")
                                results[e.value].append(e)

                            if "-" in allowed_ops:
                                e1 = combine(xe, ye, "-")
                                e2 = combine(ye, xe, "-")
                                results[e1.value].append(e1)
                                results[e2.value].append(e2)

                            if "/" in allowed_ops:
                                e1 = combine(xe, ye, "/")
                                e2 = combine(ye, xe, "/")
                                if e1 is not None:
                                    results[e1.value].append(e1)
                                if e2 is not None:
                                    results[e2.value].append(e2)

        # dedupe expressions by text per value
        compact = {}
        for val, exprs in results.items():
            seen = {}
            for e in exprs:
                seen[e.text] = e
            compact[val] = list(seen.values())

        dp[mask] = compact

    return dp

def find_equations(numbers, allowed_ops={"+", "-", "*", "/"}, use_all=False):
    dp = build_dp(numbers, allowed_ops)
    n = len(numbers)
    full = (1 << n) - 1
    out = set()

    masks = range(1, full + 1)

    for a in masks:
        b_candidates = [full ^ a] if use_all else masks
        for b in b_candidates:
            if a >= b:
                continue
            if a & b:
                continue

            common = set(dp[a].keys()) & set(dp[b].keys())
            for v in common:
                for left in dp[a][v]:
                    for right in dp[b][v]:
                        out.add(f"{left.text}={right.text}")

    return sorted(out)

For:

Python
numbers = [2, 4, 6, 8]
allowed_ops = {"+"}

You would get things like:

2+4=6
2+6=8

If use_all=True, then only equations that consume all numbers exactly once on the two sides are kept.

Complexity

Let n be the count of numbers.

There are 2^n subsets.

For each subset, you enumerate partitions, so the structural DP cost is roughly:

O(3^n)

That is standard for subset-combination DP.

The real bottleneck is how many distinct values/expressions each subset can produce.

So practical performance depends on:

  • number of numbers

  • allowed operators

  • whether you keep one expr per value or all exprs

  • whether many values collide

Best speed optimizations

If you only care about existence

Store only:

dp[mask] = set(values)

Then reconstruct later with parent pointers.

That is much faster and smaller.

If you want all equations but still fast

Store:

value -> small capped list of expressions

For example max 4 per value.

That prevents blow-up.

Canonicalization

For + and *, sort children by text or hash so:

  • 2+4

  • 4+2

collapse into one.

This removes lots of duplicates.

Integer-only pruning

If you only want integer intermediate results, reject divisions that do not divide evenly:

Python
if x.value.denominator == 1 and y.value.denominator == 1:
    allow x / y only if x.value % y.value == 0

That speeds things up a lot.

Cleaner DP variant

A very good design is to store:

dp[mask][value] = one canonical expression tree

Then:

  • fast

  • deduped

  • exact arithmetic

  • easy equality matching

Only expand to all expression strings if truly needed.

Summary of the method

Use:

  • bitmask DP over subsets

  • each subset stores all reachable values

  • combine smaller disjoint subsets to build larger ones

  • then match equal values from disjoint subsets to form lhs = rhs

This is the right dynamic-programming solution for speed.

The key optimization is:
dedupe aggressively by value and canonical expression form.

How to search disjoint subsets

Suppose for some value v you have candidate subsets:

S1 = {1,2}   -> "1+2"
S2 = {3}     -> "3"
S3 = {7,4}   -> "7-4"
S4 = {2,5}   -> "5-2"

You want to pick a collection such that no number is reused.

In bitmask form:

S1 = 00011
S2 = 00100
S3 = 11000
S4 = 10010

You need a family where:

Si & Sj == 0   for all i != j

For example:

  • S1, S2, S3 works

  • S1, S4 does not, because they both use the 2 bit

Simple implementation idea

For each value v, let:

Python
candidates[v] = [(mask, expr), (mask, expr), ...]

Then do backtracking:

Python
def search(i, used_mask, chosen):
    if i == len(cands):
        emit(chosen) if len(chosen) >= 2
        return

    # skip this candidate
    search(i+1, used_mask, chosen)

    # take this candidate if disjoint
    mask, expr = cands[i]
    if (used_mask & mask) == 0:
        chosen.append((mask, expr))
        search(i+1, used_mask | mask, chosen)
        chosen.pop()

Whenever chosen has length 2 or more, you have an equation:

expr1 = expr2 = expr3 ...

If there are many equals signs

Nothing special changes.

If you want:

A = B = C = D

you just need 4 disjoint subsets that all produce the same value.

So the general condition is:

  • pick subsets M1, M2, ..., Mk

  • all pairwise disjoint

  • all contain some expression evaluating to the same value v

Then output:

expr(M1) = expr(M2) = ... = expr(Mk)

Efficient way to think about it

The search has two layers:

Layer 1: DP

For every subset:

  • what values can it make?

Layer 2: packing

For each value:

  • which disjoint subsets can all make that value?

So the second layer is basically a set packing problem on subset masks.

Optimization for the disjoint search

If there are many candidate subsets for the same value, naive backtracking can get expensive.

Good optimizations:

1. Sort by subset size

Try smaller subsets first. They fit together more easily.

2. Deduplicate masks

If several expressions use the same mask and same value, keep only one unless you need all forms.

3. Memoize search state

Memoize by:

(index, used_mask)

if you only care about existence or max number of sides.

4. Search per value independently

This is huge. Do not mix values. For each target value v, solve disjoint packing only among subsets that make v.

Code shape

The overall code structure becomes:

Python
# phase 1: subset DP
dp = build_all_subset_results(numbers, ops)

# phase 2: invert mapping
value_to_candidates = {}
for mask in all_masks:
    for value, exprs in dp[mask].items():
        for expr in exprs:
            value_to_candidates[value].append((mask, expr))

# phase 3: for each value, find disjoint subset families
for value, cands in value_to_candidates.items():
    backtrack_over_disjoint_masks(cands)

Important detail: using all tokens or not

You may want either:

A. Any valid equation

Then just require chosen subsets are disjoint.

Example:

1+2 = 3 = 7-4

uses all numbers here, but it does not have to.

B. Use all numbers exactly once

Then in addition require:

used_mask == full_mask

at the end.

So if you have 8 numbers and produce:

1+2 = 3 = 7-4

but numbers 5,6,8 were unused, reject it.

One more example with 4 sides

Take:

numbers = [1,2,3,4,5,6,7]
ops = {+, -}

For value 3, possible disjoint subsets might be:

  • {3} -> 3

  • {1,2} -> 1+2

  • {7,4} -> 7-4

So valid 3-way:

1+2 = 3 = 7-4

Not valid 4-way if the fourth side reuses a number already used.

That is exactly what the mask intersection test catches.

With multiple = signs, you are no longer matching two subsets with the same value — you are finding a collection of pairwise disjoint subsets that all map to the same value in your DP table.

where each term is a *// chain.

So instead of DP over arbitrary binary trees, it is often better to do it in two layers:

  1. Generate all possible terms from subsets using only * and /

    A = B = C = ...

1. Why this works

Because without parentheses,

2+3*4-6/2

is really

(+ 2) + (+ 3*4) + (- 6/2)

So the side is a sum of signed terms.

A term can be:

  • a single number: 5

  • a multiplication chain: 2*4

  • a division chain: 8/2

  • mixed mult/div chain: 2*4/3, 6/2*5

You can think of a term as:

numerator-product / denominator-product

using disjoint numbers.

Example:

  • m = (3,4), d = (2) means value 3*4/2 = 6

  • m = (2,4), d = (3) means value 8/3

So yes: first build all multiplier/divider terms.

2. Phase A: build all terms

Let numbers be:

[2,3,4,6]

A term uses some subset of them.

Examples of term values:

From subset {2}:

2

From subset {2,4}:

2*4 = 8
2/4 = 1/2
4/2 = 2

From subset {2,3,4}:

2*3*4 = 24
2*4/3 = 8/3
3*4/2 = 6
2*3/4 = 3/2
4/2/3 = 2/3
...

For each subset mask, store all reachable term values:

term_dp[mask] = { value -> one or more term strings }

Example:

term_dp[{2,3,4}] might contain:
24   -> "2*3*4"
8/3  -> "2*4/3"
6    -> "3*4/2"
3/2  -> "2*3/4"

This is the multiplicative layer.

3. Then what do we do?

Now treat each term as an atomic item for the additive layer.

A full side is:

termA ± termB ± termC ...

with all term masks disjoint.

So for the next phase, define:

side_dp[mask] = all values achievable by combining disjoint terms with + and -

This can also be done by subset DP.

4. Concrete example

Take numbers:

[2,3,4,6]

Allowed operators: + - * /

We first generate terms.

Phase A: term generation

Subset {3,4,2}

Possible terms include:

3*4/2 = 6
2*4/3 = 8/3
2*3/4 = 3/2
3*4*2 = 24
4/2*3 = 6

So one entry is:

term_dp[{2,3,4}] contains:
6 -> "3*4/2"

Phase B: additive combinations of terms

Now suppose we want a side using all 4 numbers.

One way:

  • term from subset {2,3,4}: 3*4/2 = 6

  • term from subset {6}: 6

These subsets are disjoint.

So the side value:

3*4/2 - 6 = 0

That gives one side evaluating to 0.

Another split:

  • {6,3} gives term 6/3 = 2

  • {4,2} gives term 4/2 = 2

Then:

6/3 - 4/2 = 0

So both sides can make 0.

Therefore we get an equation:

3*4/2 - 6 = 6/3 - 4/2

No parentheses needed. PEMDAS handles it correctly.

5. Another concrete example with multiple =

Numbers:

[1,2,3,4,7]

Allowed ops: + - * /

Terms include:

  • {1,2} can make 2/1 = 2, 1*2 = 2

  • {3} can make 3

  • {7,4} can make 7-4 only at additive stage, not term stage

  • {7} term 7

  • {4} term 4

Now additive stage can build:

  • subset {1,2} as side 1+2 = 3? Careful: 1+2 is not a term, it is a side from two singleton terms.

  • subset {3} as side 3

  • subset {7,4} as side 7-4

So all three disjoint subsets make 3:

1+2 = 3 = 7-4

The multiplicative layer helped only where * and / exist; the additive layer then combines them.

6. Best representation

Because of PEMDAS, represent a side as:

sum of signed terms

and a term as:

product/division chain

So instead of arbitrary expression trees, use:

Side := ±Term ±Term ±Term ...
Term := n*n*n / n / n ...

This is much cleaner.

7. How to build terms efficiently

For each subset mask, split it into:

  • numerator subset N

  • denominator subset D

with:

  • N ∪ D = mask

  • N ∩ D = ∅

  • N nonempty

Then term value is:

prod(N) / prod(D)

Example with subset {2,3,4}:

  • N={3,4}, D={2} gives 3*4/2 = 6

  • N={2,4}, D={3} gives 8/3

  • N={2,3,4}, D=∅ gives 24

That means you do not even need binary DP for the term layer if you only care about normal no-parentheses chains. You can generate terms directly from numerator/denominator partitions.

That is a very good optimization.

8. Then additive DP

Once you have all terms, for each subset mask build all side values by partitioning it into disjoint term-subsets.

Example:

Numbers [2,3,4,6]

Term table might include:

mask {2,3,4} -> 6 via "3*4/2"
mask {6}     -> 6 via "6"
mask {6,3}   -> 2 via "6/3"
mask {4,2}   -> 2 via "4/2"

Now additive layer combines them:

For subset {2,3,4,6}:

  • {2,3,4} and {6}:

    • 3*4/2 - 6 = 0

    • 3*4/2 + 6 = 12

  • {6,3} and {4,2}:

    • 6/3 - 4/2 = 0

    • 6/3 + 4/2 = 4

So:

side_dp[{2,3,4,6}] contains 0 via "3*4/2-6"
side_dp[{2,3,4,6}] also contains 0 via "6/3-4/2"

9. Final equation search

After side DP, invert:

value -> list of (mask, expression)

Then for a fixed value, find disjoint masks.

Example value 0:

{2,3,4,6} -> "3*4/2-6"
{2,3,4,6} -> "6/3-4/2"

These are same mask, so not useful for equality against each other.

But if you have:

{2,3,4} -> "3*4/2" = 6
{6}     -> "6"     = 6

then disjoint masks give:

3*4/2 = 6

And if a third disjoint subset also makes 6, you get:

A = B = C

10. A full equation example from this pipeline

Numbers:

[2,3,4,6]

Phase A terms:

  • {2,3,4} -> 3*4/2 = 6

  • {6} -> 6

Phase B sides:

  • side on {2,3,4}: 3*4/2

  • side on {6}: 6

Phase C disjoint equal-value match:

  • masks disjoint

  • same value 6

Output:

3*4/2 = 6

Another valid one:

  • {6,3} -> term 6/3 = 2

  • {4} -> side 4

  • {2} -> side 2

Additive layer on {4,2}:

4-2 = 2

Now {6,3} and {4,2} are disjoint and both make 2, so:

6/3 = 4-2

That is a complete equation from the two-layer method.

11. So the concrete algorithm is

Phase 1: term generation

For every subset:

  • enumerate numerator/denominator splits

  • compute prod(num)/prod(den)

  • store canonical term string

Phase 2: side generation

For every subset:

  • either use it as one term

  • or split into disjoint smaller subsets and combine sides with + or -

This gives all PEMDAS-valid no-parentheses sides.

Phase 3: equality packing

Group by value, then find disjoint masks producing the same value.

12. Why this is better than generic expression DP

Because generic DP builds lots of equivalent trees like:

(2*3)/4
2*(3/4)

But with no parentheses and PEMDAS, these are really just multiplicative terms.

So the search space shrinks a lot if you separate:

  • multiplicative term construction

  • additive side construction

  • equality grouping

13. Practical formula

Think of each side as:

Σ s_i * ( Π numerators_i / Π denominators_i )

where:

  • each s_i is +1 or -1

  • all numbers are used at most once on that side

That is the structure your DP should target.
